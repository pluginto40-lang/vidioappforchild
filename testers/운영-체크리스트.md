# 비공개 테스트 운영 체크리스트 (운영자용)

> 🔒 **개인정보는 저장소에 절대 적지 마세요.** 이 저장소는 공개돼 있어요.
> 테스터 이름·이메일·설문 답변은 **내 구글 드라이브의 비공개 스프레드시트**에만 두세요.
> 이 파일에 체크 표시를 하고 싶다면 "12명 참여 확인 ✅"처럼 **숫자만** 적으세요.

---

## 0. 목표 인원: 15명 이상 (가능하면 20명)

- 공식 최소 인원은 12명이에요. 하지만 14일 안에 한 명이라도 빠지면("테스트 그만두기"를 누르거나, 폰·계정이 바뀌면) 그 사람은 숫자에서 빠져요.
- 그래서 **15명 이상**을 목표로 하세요. 3명이 빠져도 12명이 남아요.
- 아이폰 쓰는 지인은 참여가 안 되니 미리 걸러 주세요.

---

## 1. 테스터 이메일 받는 법: **이메일 목록** 추천 ✅

Play Console에는 두 가지 방법이 있어요.

| | 이메일 목록 (추천) | 구글 그룹 |
|---|---|---|
| 방법 | Play Console에 이메일을 직접 붙여 넣기 | 구글 그룹을 만들고 테스터가 그룹에 가입 |
| 테스터가 할 일 | 링크 열고 "테스터 되기"만 누르면 끝 | **그룹 가입** + 링크 열고 "테스터 되기" (한 단계 더) |
| 운영자가 할 일 | 이메일을 받아서 붙여 넣기 | 그룹 만들기, 가입 승인 관리 |
| 장점 | 단계가 적어서 테스터가 덜 헷갈려요 | 이메일을 일일이 안 받아도 돼요 |

**추천: 이메일 목록.** 20명 정도라 붙여 넣기도 금방이고, 테스터(특히 육아로 바쁜 부모님)가 따라 할 단계가 하나 줄어서 실수가 적어요.

### 이메일 목록 만드는 법
1. 내 구글 드라이브에 **비공개** 스프레드시트를 만들어요. (이름 예: "테스터 명단 - 비공개")
   - 칸: 이름(별명) / 이메일 / 받은 날 / 참여 확인 / 설문 응답 여부
   - ⚠️ 공유 설정은 **"나만"** 으로 두세요.
2. Play Console → 내 앱 → **테스트 → 비공개 테스트** → 트랙 선택 → **테스터** 탭 → **"이메일 목록 만들기"**
3. 이메일을 쉼표 없이 **한 줄에 하나씩** 붙여 넣고 저장해요.
4. "의견 보내기 URL 또는 이메일" 칸에 의견 받을 주소(설문 링크나 내 이메일)를 넣어요.
5. 앱 파일(AAB)을 이 트랙에 올리고 검토를 보내요. 통과 후 **참여 링크**가 생겨요. (처음엔 몇 시간 걸릴 수 있어요)

## 2. 날짜별 할 일

> **1일차 = 12번째 테스터가 "테스터 되기"를 누른 날**로 잡으면 안전해요. 사람마다 14일을 따로 세기 때문이에요.
> 1일차 날짜를 달력(예: 구글 캘린더)에 적고 7일차, 14일차, 15일차 알림을 미리 맞춰 두세요.

### 시작 전 (모집 기간)
- [ ] [모집-메시지.md](모집-메시지.md)로 지인·단톡방·육아 카페에 알리기
- [ ] 받은 이메일을 비공개 스프레드시트에 모으기 (15명 이상)
- [ ] 플레이스토어 로그인 계정과 같은 이메일인지 한 번 더 확인
- [ ] 의견 받을 설문(아래 4번) 미리 만들어 두기

### 1일차 (참여 링크 보내는 날)
- [ ] Play Console에 이메일 목록 등록 & 참여 링크 복사
- [ ] [참여-방법.md](참여-방법.md) 내용 + 참여 링크를 테스터에게 개인 메시지로 보내기
- [ ] 테스터가 "설치했어요"라고 답하면 스프레드시트에 표시
- [ ] 안 된다는 분 도와드리기 (대부분 **다른 구글 계정으로 링크를 연 경우**예요)
- [ ] 12명 이상 확인되면 그날을 **1일차**로 달력에 적기
- [ ] Play Console에서 참여 인원 숫자 확인 (화면 위치는 바뀔 수 있어요. 비공개 테스트 트랙 화면을 둘러보세요)

### 3~5일차 (가볍게)
- [ ] "앱 잘 쓰고 계세요? 가끔 한 번씩만 열어 주세요 🙏" 정도의 짧은 안부 메시지
- [ ] 버그나 불편 신고가 오면 메모 (→ 5번 "신청서 메모장"에)

### 7일차 (중간 점검)
- [ ] 설문 링크 보내기 (아래 4번)
- [ ] 참여 인원이 12명 아래로 떨어졌는지 확인
  - 떨어졌다면: **바로 추가 모집**. 새로 들어온 사람은 그날부터 14일을 다시 세야 해서 전체 일정이 늦어져요.
- [ ] 받은 의견 중 쉽게 고칠 수 있는 건 고쳐서 새 버전 올리기 (테스터는 앱을 지울 필요 없이 업데이트만 받으면 돼요)
- [ ] "삭제하지 말고, 테스트 그만두기도 누르지 말아 주세요" 다시 한 번 부탁

### 14일차 (마무리)
- [ ] 설문 아직 안 한 분께 한 번 더 부탁
- [ ] 참여 인원이 **여전히 12명 이상**인지 확인
- [ ] "아직 지우지 말아 주세요! 신청 끝나면 알려드릴게요" 메시지 보내기
  - 신청하는 **그 순간**에도 12명 이상이 참여 중이어야 해요

### 15일차 이후 (신청)
- [ ] 5번 메모장 내용을 보고 Play Console 대시보드 → **프로덕션 액세스 신청** 작성
- [ ] 신청 후 보통 7일 이내 결과 이메일이 와요. 결과 올 때까지 테스터에게 앱을 지우지 말아 달라고 부탁해 두면 안전해요
- [ ] 승인되면 테스터에게 감사 메시지 + 스프레드시트에서 **이메일 지우기**

---

## 3. 중간에 빠지는 사람 대비

- **15명 이상**으로 시작하기
- 모집 때 "예비로 들어와 줄 수 있는 분" 2~3명을 따로 알아 두기
- 테스터에게 **"테스트 그만두기"를 누르지 말라고** 두 번 이상 안내 (1일차, 7일차)
- 폰을 바꾸거나 초기화할 예정인 분은 미리 알려 달라고 부탁하기

---

## 4. 의견 받는 방법: 구글 설문지 (질문 5개)

**구글 설문지(Google Forms)** 를 추천해요. 무료고, 답이 스프레드시트로 자동 정리돼요.
- 설문지에서 **이메일 수집은 끄세요.** 이름도 묻지 마세요. (익명이 솔직한 의견을 받기 좋아요)
- 설문 답변도 저장소에 붙여 넣지 말고, 신청서에는 **요약만** 쓰세요.

### 질문 5개 (제안)

1. **아이 나이대와 고민을 고르는 과정은 쉬웠나요?** (1~5점)
2. **추천된 영상이 우리 아이에게 잘 맞았나요?** (1~5점)
3. **"오늘은 여기까지" 화면 덕분에 시청을 끝내기 쉬웠나요?** (예 / 아니요 / 아직 못 봤어요)
4. **써 본 기능을 모두 골라 주세요.** (여러 개 선택: 나이대 고르기 / 고민 고르기 / 편수 정하기 / 영상 보기 / "오늘은 여기까지" 화면 / 부모 확인 / 기타)
   → 신청서의 "테스터가 모든 기능을 써 봤나요?" 질문에 바로 쓸 수 있어요
5. **불편했던 점이나 바라는 점을 자유롭게 적어 주세요.** (주관식. 재생 안 된 영상이 있으면 알려 주세요)

---

## 5. 출시 권한 신청서 답 미리 모으는 법

신청서는 작성 중에 나가면 **저장이 안 돼요.** 그래서 14일 동안 아래 메모장을 **내 컴퓨터나 구글 드라이브(비공개)** 에 만들어 두고 조금씩 채우세요.

### 신청서 메모장 (복사해서 쓰세요)

```
[비공개 테스트]
- 모집 난이도: (쉬웠음 / 보통 / 어려웠음) — 어디서 몇 명 모았는지(숫자만)
- 테스터 사용 모습: 설문 4번 결과 요약 (예: 15명 중 13명이 모든 기능 사용)
- 실제 사용자와 비슷했나? 다른 점은? (예: 테스터는 부모 지인이라 실제 대상과 같음. 다만 아이 나이대가 ○~○세에 몰림)
- 의견 요약: 많이 나온 의견 3가지
- 의견 모은 방법: 구글 설문지(7일차·14일차) + 카카오톡 개별 메시지

[앱]
- 대상 사용자: 0~○세 영유아를 키우는 부모
- 가치: 아이 나이와 육아 고민에 맞는 영상을 골라 주고, 정한 편수만 보면 끝나서 부모가 시청 시간을 관리하기 쉬움
- 첫해 예상 설치 수: (보기 중 고르기)

[출시 준비]
- 테스트 후 고친 점: (날짜 - 고친 내용) 예: ○일차 - 재생 안 되는 영상 교체
- 출시 준비 판단 근거: 치명적 오류 신고 없음, 설문 만족도 평균 ○점, 받은 의견 반영 완료
```

### 팁
- **고친 점은 생길 때마다 날짜와 함께** 적어 두세요. 신청서에서 가장 중요하게 보는 부분 중 하나예요.
- 의견이 하나도 없으면 "고친 점"을 쓰기 어려워요. 7일차 설문을 꼭 보내세요.
- 대상 사용자에 "아이"라고만 쓰지 말고 **"부모가 쓰는 앱"** 임을 분명히 적으세요.
